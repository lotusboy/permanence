## Permanence protocol (Tier 2 — non-Claude-Code agents)
At the start of a session in any project directory, run `~/permanence/runtime/session-start.sh` and follow its output: it resolves the current directory through `~/permanence/_meta/REGISTRY.md` and says which Permanence stream (if any) to read before starting work. If you can't run shell commands, read `~/permanence/_meta/REGISTRY.md` yourself to find the mapped stream, then read that stream's `PROJECT.md`, `QUESTIONS.md`, and the tail of `LOG.md`. No meaningful working directory to resolve (a chat-style session)? Ask which project by name instead, and look for a matching row in `_meta/REGISTRY.md`'s stream column directly. Update the active stream's files whenever something material changes, without being asked — see `~/permanence/SPEC.md` for the full contract. Never reference Permanence's paths or contents in any file committed to a project repository (one-way flow).

### In every session

**Drift count (a tiredness proxy).** You cannot feel your own error rate rise, so count it. Each session, from zero, count three kinds of event: a scratch-script error (a one-off measurement reported, or nearly reported, wrong); a self-contradiction (a later check of the same thing gives a different number); a re-derivation error (a fact established earlier in the session rebuilt from memory, wrongly). At 3, say so in one line and switch method: use tested code paths, and cross-check each new number before reporting it. At 5, recommend stopping. Report it as a rate, not a crisis. It tends to rise with novel one-off scripts, long runs of "keep going", and very long contexts.
